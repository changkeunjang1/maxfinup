1. 서론

본 과제는 TrafficLens 시스템을 통해 YOLOv8 모델로 도로 영상 속 차량과 보행자를 실시간으로 탐지하고, 종류별 개수를 화면에 표시하는 시스템을 구현한다.

1.1 연구 배경

도로 위 차량과 보행자를 사람이 직접 감시하는 방식은 인력과 시간이 많이 들고, 놓치는 상황이 생기기 쉽다. 딥러닝 기반 객체 탐지 기술은 CCTV나 차량 카메라 영상에서 객체를 자동으로 찾아내 이 문제를 줄일 수 있다. 특히 YOLO는 속도가 빨라 실시간 처리가 필요한 교통 분야에 적합하다.

1.2 연구 목적

  • 사전 학습된 YOLOv8 모델로 차량(승용차, 버스, 트럭, 오토바이)과 보행자를 탐지한다.
  • 탐지된 객체를 종류별로 세어 화면에 실시간으로 표시한다.
  • 모델 크기별 정확도(mAP)와 처리 속도(FPS)를 비교해 실시간 적용 가능성을 확인한다.

1.3 활용 분야

  • 스마트 교차로의 신호 제어와 교통량 조사
  • 어린이 보호구역의 보행자 감지 및 경고
  • 자율주행 차량의 주변 인식

2. YOLO 개요

YOLO(You Only Look Once)는 이미지를 한 번만 보고 객체의 위치와 종류를 동시에 예측하는 1단계(one-stage) 객체 탐지 모델이다.

2.1 동작 원리

  1. 입력 이미지를 일정한 크기(예: 640×640)로 맞춘다.
  2. 백본(Backbone) 네트워크가 이미지의 특징을 추출한다.
  3. 넥(Neck)이 여러 크기의 특징을 합쳐 작은 객체와 큰 객체를 모두 찾을 수 있게 한다.
  4. 헤드(Head)가 바운딩 박스 좌표, 클래스, 신뢰도(confidence)를 출력한다.
  5. NMS(Non-Maximum Suppression)로 같은 객체에 겹친 박스를 하나만 남긴다.

2.2 2단계 탐지기와의 비교

구분2단계 (Faster R-CNN 등)1단계 (YOLO)
처리 방식후보 영역 추출 후 분류한 번에 위치와 클래스 예측
속도느림빠름 (실시간 가능)
적합한 용도정밀 분석영상·웹캠 실시간 처리

2.3 주요 버전

버전발표특징
YOLOv12016최초의 YOLO, 실시간 탐지 개념 제시

5. 시스템 설계 및 구현

시스템은 영상 프레임마다 탐지와 추적을 거쳐, 현재 화면의 개수(now), 기준선 통과 개수(line), 누적 등장 개수(total)를 함께 표시한다.

5.1 처리 흐름

입력도로 영상 · 웹캠
YOLOv8 탐지교통 5개 클래스
ByteTrack 추적객체마다 ID 부여
카운팅now · line · total
출력화면 표시 · 저장

↻ 다음 프레임으로 반복

한 프레임의 처리가 끝나면 다음 프레임으로 돌아가며, 추적 ID는 프레임이 바뀌어도 유지되어 누적 개수가 중복 없이 쌓인다.

5.2 핵심 기능

  • 클래스 필터링: classes=[0, 2, 3, 5, 7]로 보행자와 차량 4종만 탐지한다.
  • 작은 보행자 대응: 높은 곳에서 찍은 영상은 사람이 약 20픽셀로 작아, YOLOv8s 모델과 1280 추론 해상도를 쓰고 보행자 신뢰도 기준만 0.25로 낮췄다 (차량은 0.4).
  • 객체 추적(ByteTrack): model.track(persist=True)가 같은 객체에 프레임이 바뀌어도 같은 ID를 붙인다.
  • 기준선 통과 카운팅(line): 화면에 기준선을 긋고, 객체 중심점의 이동 경로가 선을 가로지르면 방향별로 한 번만 센다.
  • 누적 카운팅(total): 클래스별로 처음 본 추적 ID를 집합(set)에 넣어 센다.
  • 화면 표시: 클래스별 색상 박스, 신뢰도와 ID 라벨, 노란 기준선(통과 순간 초록으로 깜빡임), now·line·total 집계표, FPS를 그린다.
  • 결과 저장: 처리된 영상을 result.mp4로 저장한다.

5.3 핵심 코드

전체 코드는 traffic_detect.py(약 200줄, 내려받기)이며, 아래는 기준선 통과 판정과 카운팅 부분이다.

{% verbatim %}def crossed(p_prev, p_now, a, b):
    """이동 경로(p_prev -> p_now)가 기준선 a-b를 가로질렀으면 방향(+1/-1), 아니면 0"""
    s1, s2 = side(p_prev, a, b), side(p_now, a, b)
    if s1 == 0 or s1 * s2 > 0:
        return 0
    if side(a, p_prev, p_now) * side(b, p_prev, p_now) > 0:   # 선분 범위 밖
        return 0
    return 1 if s2 > 0 else -1

results = model.track(frame, classes=list(TARGET_CLASSES), conf=0.25, imgsz=1280,

6.4 분석

  • 잘 된 점: 화면에 동시에 있는 차량 50~60대를 대부분 탐지했고, 기준선 통과 승용차는 양방향 75대·71대로 고르게 집계됐다.
  • 작은 보행자: 사람이 약 20픽셀로 작아 기본 설정(YOLOv8n·640)에서는 한 장면에 1명만 잡혔다. YOLOv8s·1280으로 바꾸자 5명으로 늘었지만, 횡단보도 위 보행자는 여전히 자주 놓쳤다.
  • 오탐지: 신호등이 보행자(Person)로 잡히는 경우가 많았다. 보행자 신뢰도 기준을 0.25로 낮춘 대가다. (6.5절에서 개선)
  • 클래스 혼동: 짐칸 트럭이 버스로 잡히는 등, 같은 차가 프레임마다 클래스가 바뀌었다.
  • total이 부풀려짐: 차가 다른 차나 기둥에 가려졌다 나타나면 새 ID가 붙고, 클래스가 바뀌면 다른 클래스에도 집계돼 버스 total이 125까지 올랐다. 실제 교통량은 line 값이 더 믿을 만하다. (6.5절에서 개선)
  • 속도: CPU(i5-6600)에서는 약 2.4 FPS로 90초 영상에 19분이 걸렸지만, GPU(GTX 1060)로 바꾸자 약 11 FPS, 238초로 줄었다. 탐지만 보면 27.8 FPS이므로, 남은 병목은 추적·화면 그리기·영상 저장이다.

6.5 개선 실험: 오탐지와 total 부풀림 줄이기

6.4절에서 찾은 문제 세 가지를 고친 개선 버전을 같은 90초 영상에 돌린 결과, 차량 total은 753에서 485로(36% 감소), 보행자 total은 75에서 35로(53% 감소) 줄었고 교통량(line)은 그대로 유지됐다.

문제개선 방법
신호등이 보행자로 오탐지위치 기반 정지 물체 필터: 화면을 32픽셀 칸으로 나눠, 20초 이후 지금까지 프레임의 15% 이상 '보행자'가 나온 칸의 보행자는 제외한다. 신호등은 탐지가 끊겼다 이어지며 ID가 계속 바뀌므로 ID가 아니라 위치로 판단한다.
트럭·버스 클래스 혼동클래스 다수결: 추적 ID별로 지금까지 가장 많이 나온 클래스를 쓴다.
잠깐 나타난 ID로 total 부풀림짧은 추적 제거: 5프레임보다 짧게 보인 ID는 total에서 뺀다.

  • 정지 물체 필터: 21개 ID가 정지 물체로 판정됐다. 6.3절 두 번째 캡처와 같은 장면에서 신호등 5개 중 3개가 걸러졌고, 영상 후반에 처음 나타난 2개는 비율이 기준에 못 미쳐 남았다.
  • 클래스 다수결: 차량 line 합계는 151로 같고, 승용차 2대가 트럭으로 다시 분류됐다. 버스 total은 125에서 67, 트럭 total은 97에서 27로 줄었다.
  • 한계: 신호등 위치의 '보행자' 비율은 18~45%였지만, 실제 보행자가 신호를 기다리는 모퉁이도 28%가 나왔다. 그래서 이 필터는 한자리에 오래 서 있는 진짜 보행자도 뺄 수 있다.
  • 속도: 영상을 저장하지 않는 같은 조건에서 기본 16.7 FPS, 개선 16.8 FPS로 차이가 없었다. 1080p 결과 영상을 저장하면 약 11.9 FPS로 떨어져, 속도를 가장 많이 잡아먹는 것은 영상 저장이었다.

개선 기능은 PC용 traffic_detect.py에 기본으로 들어 있고(--baseline으로 끌 수 있음), 이 실험은 Colab 노트북 TrafficLens_Colab.ipynb(내려받기)의 실험 2·3으로 그대로 재현할 수 있다.

7. 결론 및 향후 개선점

YOLOv8과 ByteTrack을 결합해, 별도 학습 없이도 도로 영상에서 차량과 보행자를 탐지하고 기준선을 지나는 교통량을 종류별로 셀 수 있음을 확인했다. 처리 속도는 GPU로 바꾸자 CPU 대비 약 4.8배 빨라졌지만, 전체 처리 기준 약 11 FPS로 실시간(30 FPS)에는 아직 못 미쳤다.

7.1 결론

  • 사전 학습 모델과 클래스 필터만으로 교통 객체 5종을 탐지할 수 있었다.
  • 기준선 통과 카운팅으로 90초 동안 승용차 146대의 교통량을 방향별로 집계했다. 누적 ID(total)는 가림과 클래스 혼동으로 부풀려졌지만, 클래스 다수결·짧은 추적 제거·위치 기반 정지 필터로 차량 36%, 보행자 53%를 줄였다.
  • 높은 곳에서 찍은 영상의 작은 보행자는 모델과 해상도를 키워야 잡혔고, 그만큼 속도가 떨어졌다 (CPU 2.4 FPS → GPU 약 11 FPS).

7.2 향후 개선점

  1. 실시간 처리: GPU 적용으로 탐지는 27.8 FPS까지 올랐으므로, 영상 저장을 끄거나 화면 그리기를 줄여 전체 처리도 실시간에 가깝게 만든다.
  2. 보행자 오탐지 줄이기: 위치 기반 필터는 신호등 5개 중 3개만 걸렀다. 후반에 나타난 신호등까지 잡도록 판단 방식을 다듬고, 기다리는 보행자와 구분하려면 높은 시점의 보행자 데이터로 추가 학습한다.
  3. 크게 나눠 탐지(타일링): 화면을 여러 조각으로 나눠 탐지하면 작은 보행자를 더 잘 찾을 수 있다.
  4. 영상 저장 속도: 1080p 결과 영상 저장만으로 16.8 FPS가 11.9 FPS로 떨어진다. 저장 해상도를 낮추거나 별도 스레드에서 저장해 속도를 되찾는다.
  5. 한국 도로 데이터 학습: AI Hub 데이터로 fine-tuning해 국내 버스·트럭 인식률을 높인다.
